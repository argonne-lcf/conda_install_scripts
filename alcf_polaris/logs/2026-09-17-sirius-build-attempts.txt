Assessment (2026-09-22): biggest changes, uncertain choices, what to drop
=========================================================================

Biggest changes to the script, in order of blast radius
-------------------------------------------------------
1. CUDA 13.0.3 with cuDNN 9.26 / NCCL 2.30.7. Deliberate, and the harness validates it, but it is
   the one change that touches every binary in the env.
2. torch 2.14 moved the goalposts: PEP 517 build only, and every extension must compile as C++20.
   That single fact caused attempts 7, 8 and 11 and forced the gcc-14 pin, the pip_sdist_cxx20 sed
   patch, and the DeepSpeed builder sed.
3. Deleting TF's pywrap_dlopen_global_flags.py. Not a build change, an edit to the installed TF
   package, but without it TF and anything triton-based cannot share a process.
4. The script grew a resume/retry layer (17 guards, gclone, repair_cmake, have_pkg). It is what
   made 22 attempts survivable in a day, but it is ~200 lines of machinery a from-scratch run never
   exercises.
5. vLLM build parallelism 4 -> 32 and the TE 2.19 knob set (NCCL_HOME, NVTE_WITH_NCCL_EP=0,
   CUDNN_PATH, NVTE_CMAKE_EXTRA_ARGS).

Choices flagged as uncertain, most to least
-------------------------------------------
- Rewriting -std=c++17 -> c++20 inside flash-attn's and mamba-ssm's sdists. Upstream has never
  tested that combination. Both pass a one-shot forward smoke test, nothing more.
- vLLM v0.29.0 compiled against torch 2.14 when it pins 2.13.0; use_existing_torch.py leaves the
  tree dirty so it reports as 0.29.1.dev0+... Only `import vllm` is tested; no model was served.
- The TF hook deletion. Sound by TF's own docstring, but the wheel in wheels/ and the installed
  package now differ.
- What vLLM's uv resolve did to the env: replaced conda numpy/numba with pip ones (conda then put
  numpy 2.5.3 back, so `conda list` shows both), moved tilelang and apache-tvm-ffi past mamba-ssm's
  pins, and substituted PyPI flashinfer-python for the source build.
- Installed but never exercised for real use: onnxruntime's TRT provider (only listed), the Globus endpoint (imports, but
  three of its hard pins are violated), tensorflow_probability 0.25 (a 2024 release under TF 2.21 /
  Keras 3, never imported by any test), onnx-tf (effectively dead upstream).
- Unpinned master checkouts for h5py (3.17.dev0, violates TF's <3.15), xgboost (3.5.0-dev),
  cutlass, apex, numpyro, DeepHyper. A reproducibility hole, not a correctness one.

Recommendation: drop things
---------------------------
The mess concentrated in the torch-extension ecosystem that hand-rolls its own nvcc flags.

  Drop                        Why
  --------------------------  ----------------------------------------------------------------------
  mamba-ssm + causal-conv1d   Needed the sdist patch; hard-pins tilelang/apache-tvm-ffi that vLLM
                              immediately breaks; niche user base.
  verl                        Installed --no-deps, and its transformers<5.11 is the only reason the
                              whole env is held at 5.10.4. Removing it lets transformers float.
  apex                        NVIDIA has deprecated it; Megatron-LM and TE carry the fused ops now.
                              Slow to build, no known users.
  Megatron-DeepSpeed          Unpinned git master of a stale fork.
  onnx-tf, tensorflow_probability
                              Unmaintained against TF 2.21; likely broken and never tested.
  (DeepSpeed evoformer op)    Considered dropping; keep it. It is the DS4Sci_EvoformerAttention kernel
                              OpenFold uses, still maintained upstream (fix landed 2026-03-13), and it
                              built cleanly once the C++20 patch was in.

Keep flash-attn: it is the messiest but also the most requested
(attn_implementation="flash_attention_2" everywhere), and the patch is now a one-liner that either
compiles or does not. If it bites again on torch 2.15, the fallback is the mjun0812 prebuilt wheels.

Two cheap hardening items regardless: pin h5py, xgboost, cutlass and numpyro to release tags, and
add --no-deps plus explicit dep lists around vLLM so its resolver cannot rewrite the env.

Options from here: make those cuts in the script and run one more resume so the live env matches
(removals are pip uninstalls, a few minutes), or leave the env as-is and apply the trimmed script
on Polaris.
